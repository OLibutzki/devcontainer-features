# Dev Container Features

Dev container features published to GitHub Container Registry, following the
[devcontainers/feature-starter](https://github.com/devcontainers/feature-starter) conventions.

| Feature | Version | Description |
| --- | --- | --- |
| [`claude-code`](src/claude-code) | `0.0.3` | Installs Anthropic's Claude Code CLI with the recommended native installer — no Node.js required. |
| [`rootless-podman`](src/rootless-podman) | `0.0.1` | Installs rootless Podman as a Docker-compatible container engine (DOCKER_HOST, testcontainers) without a privileged container. |

> **The 0.x stream is experimental.** Options can be renamed, removed or have their defaults reversed in
> any release before `1.0.0`. Pin the exact patch version, never the rolling `:0` / `:0.0` tags.

## Usage

```jsonc
{
    "image": "mcr.microsoft.com/devcontainers/base:ubuntu",
    "remoteUser": "vscode",
    "features": {
        "ghcr.io/olibutzki/devcontainer-features/claude-code:0.0.3": {}
    },
    // Sign in automatically when the host has a token; falls back to browser
    // login when it does not. Safe to commit.
    "remoteEnv": {
        "CLAUDE_CODE_OAUTH_TOKEN": "${localEnv:CLAUDE_CODE_OAUTH_TOKEN}"
    },
    // Without this you sign in again after every rebuild.
    "mounts": [
        "source=claude-code-config-${devcontainerId},target=/home/vscode/.claude,type=volume"
    ]
}
```

Those two consumer-side lines cannot be moved into the feature — a feature cannot substitute a *host*
value, and cannot know your `remoteUser`'s home directory. Everything that makes them work is handled by
the feature. See [the feature's notes](src/claude-code/NOTES.md) for options, authentication, the
`~/.claude` volume, and the egress-firewall template this pairs with.

## Repository layout

```
├── .devcontainer/              # this repo's own container: the feature behind an egress firewall
├── src/
│   ├── claude-code/             # devcontainer-feature.json, install.sh, NOTES.md
│   └── rootless-podman/         # devcontainer-feature.json, install.sh, NOTES.md
├── test/
│   ├── claude-code/             # test.sh + scenario tests
│   └── rootless-podman/         # test.sh + scenario tests
└── .github/workflows/
    ├── release.yaml            # publishes to ghcr.io (run manually from the Actions tab)
    └── test.yaml               # runs `devcontainer features test` on every push/PR
```

`src/<feature>/README.md` is **generated** from `devcontainer-feature.json` + `NOTES.md` by the release
workflow. Do not hand-edit it; edit `NOTES.md` instead.

## Releasing

Bump the `version` field in the feature's `devcontainer-feature.json` (semver), then trigger the **Release
dev container features & Generate Documentation** workflow manually on `main`. It publishes to
`ghcr.io/olibutzki/devcontainer-features/<feature-id>`.

First-time repository setup: the first publish creates the package as **private** (make it public under
*Packages → Package settings*), and *Settings → Actions → General → Workflow permissions* needs read/write
plus *Allow GitHub Actions to create and approve pull requests* for the documentation PR step.

## Local development

```bash
npm install -g @devcontainers/cli

# autogenerated tests (default options), per base image
devcontainer features test --skip-scenarios -f claude-code -i mcr.microsoft.com/devcontainers/base:ubuntu .
devcontainer features test --skip-scenarios -f rootless-podman -i mcr.microsoft.com/devcontainers/base:ubuntu .

# scenario tests
devcontainer features test -f claude-code --skip-autogenerated --skip-duplicated .
devcontainer features test -f rootless-podman --skip-autogenerated --skip-duplicated .
```
